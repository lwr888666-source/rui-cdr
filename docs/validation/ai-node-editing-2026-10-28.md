# AI node editing implementation and validation

Implementation tested: `8b496569a9ccbf2318ae8a63f16a2bbcb3c3744d`.
Full validation: https://github.com/lwr888666-source/rui-cdr/actions/runs/40705261400

## Cause and original call chain

The reported Chinese refusal is not a repository string or a hardcoded rejection
branch. It was generated by the AI service and printed by its script.
`print()` calls the common JavaScript `__call('log', ...)` bridge and appends to
`HostInner.output`; it does not edit the drawing.

The original chain was `App::ai_draw` -> page description and system reference ->
provider request -> reply parsing -> JavaScript extraction -> Boa evaluation ->
native script dispatcher -> recorded commands -> `Engine::run_batch`.
The page description contained bounds and styles, not real vector nodes. The AI
reference omitted the existing `Curve.Nodes` methods. Those methods exposed
anchors but not handles; their move operation also normalized quadratics and
used only the object's transform, losing ancestor transforms. Their generic
shape replacement was unsuitable for strict coordinate-only repairs.

The model already used native `kurbo::BezPath`, with `MoveTo`, `LineTo`,
`QuadTo`, `CurveTo` and `ClosePath`, node type overrides and optional spline
controls. Core commands and snapshot history already provided atomic batches
and Undo/Redo. The old scripting apply function swallowed engine failures, and
print-only scripts could produce the misleading completed status with zero
changes.

## Implemented chain

`App::ai_draw` now obtains selected geometry through the native reader before
sending the model request. Selected requests do not include unrelated layers.
The system reference documents the real read and patch methods. The returned
program calls the registered `ActiveDocument` methods through the existing
`__td` dispatcher. It reads current geometry, selects explicit coordinate edits,
and records `Command::EditPathNodes`. Successful programs commit through the
existing engine batch once. The canvas observes the new engine revision.

Node requests enter a restricted mode before evaluation. The original selection,
page and document revision are preserved or checked. Script selection cannot
expand the writable scope. A caught validation error still invalidates the
whole script. Final checks preserve unrelated document data and refuse edits
that would trigger regeneration of linked or generated objects.

## Actual script API

```javascript
const selected = ActiveDocument.GetSelectedVectorGeometry();
// Choose an object and node from selected.objects using their real geometry.
const object = selected.objects[0];
const result = ActiveDocument.ApplyPathNodeEdits([{
  shape_id: object.shape_id,
  geometry_token: object.geometry_token,
  coordinate_space: 'local',
  preserve_bounds: true,
  edits: [{node_index: 5, position: {x: 50, y: 50}}]
}]);
print(result.changed_nodes);
```

The example coordinates and index belong to the regression fixture. Node indices
are zero-based original path element indices, not node-array positions. Units
are millimetres; page origin is bottom-left and y points up. The reader returns
local and page coordinates for anchors and handles, exact segment records,
open/closed subpaths, original object IDs and composite ancestor transforms.
`position`, `in_handle` and `out_handle` are optional absolute coordinates;
omitted coordinates retain their exact stored values. No SVG serialization,
normalization, object replacement or implicit handle movement occurs.

The patch result contains actual `changed_nodes` and updated geometry/tokens.
The UI counts unique nodes differing in the final document. A net-zero script
creates no history entry and displays no changes. Any failing script applies
zero changes. See `../behavior/ai-node-editing.md` for the complete contract.

## Limits

- Model inference depends on the configured service. Integration tests use a
  deterministic transport returning a program that decides from actual neighbour
  coordinates, not hardcoded IDs, indices or successful return values. They do
  not validate a third-party model's visual judgement.
- Native paths are supported. Rectangles, ellipses, text, bitmaps, groups,
  symbols and B-spline outlines report an explicit unsupported reason instead
  of being converted. A path inside a plain group includes its parent transform.
- AI patches preserve outer page-space bounds. An extremum repair that changes
  overall size is refused. Quadratic shared controls require both handle aliases.
- Generated connectors, callouts, dimensions, raster effects, clipping
  boundaries and paths driving linked blends/connectors are guarded to prevent
  later frame refreshes changing other objects.
- Context embeds at most 2048 selected nodes; the script reader allows a total
  budget of 100000. Per-object paths have at most 100000 elements; a batch has at
  most 256 objects and 4096 edits per object. Coordinates must be finite and
  within 1000000000 mm. Invalid or stale edits leave the original drawing intact.
